## Re-execution Note

This is a full, independent re-run of the CARSHOP-101 validation. The
underlying requirements are unchanged. Since the prior run, two dedicated
follow-up tasks that were opened from that run's findings have already been
implemented in the repository:

- **CARSHOP-102** — the `GET /works?includeDrafts=true` authorization gap.
  `src/infra/http/routes/work.routes.ts` now applies
  `requireAuthForDraftsMiddleware` (`src/infra/presentation/middleware/require-auth-for-drafts.middleware.ts`),
  which only requires authentication when `includeDrafts=true` is
  requested. This is documented in `src/infra/docs/works.swagger.ts` and
  covered by a unit test
  (`test/unit/infra/presentation/middleware/require-auth-for-drafts.middleware.spec.ts`)
  and a permanent E2E regression test (`test/e2e/works.e2e-spec.ts`).
- **CARSHOP-103** — E2E automation for the coverage gaps identified in the
  prior run. `test/e2e/*.e2e-spec.ts` now contains 6 spec files (up from 1)
  covering works CRUD, comment moderation, work-image upload/delete, and
  admin work hard-delete, including the image-cascade branch, using a new
  `FakeImageStorageAdapter` (`test/e2e/support/fake-image-storage.adapter.ts`)
  injected through `createApp({ imageStorage })`
  (`src/infra/server.ts`'s new `CreateAppOverrides`).

This re-run independently re-verifies all of this evidence rather than
trusting the prior report's conclusions, per the task's explicit
instruction. Findings that reproduce the prior run's gaps reference
CARSHOP-102/CARSHOP-103 instead of recommending new duplicate follow-up
tasks (FR-012/AC-010). One residual minor gap not covered by either
existing follow-up task is flagged as a new observation (see "New
Observations" below).

## Method

- Endpoint inventory rebuilt from the real composition-root sources of
  truth: `src/infra/config/routes.ts`, `src/infra/http/routes/*.routes.ts`,
  and the served `GET /docs.json` document (assembled from
  `src/infra/docs/*.swagger.ts`). Every row below is traceable to a
  `router.<method>(...)` registration confirmed by direct file reads in
  this session.
- Endpoints were exercised by running the project's **existing, permanent**
  E2E suite (`npx jest --config ./test/jest-e2e.json`) against `createApp()`
  (the real composition root), using the project's `mongodb-memory-server`
  harness (`test/e2e/setup/mongo-memory-server.global-setup.ts` /
  `global-teardown.ts`, wired through `test/jest-e2e.json`). `MONGO_URI` is
  generated by the in-memory server, not read from a real environment.
  `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `JWT_EXPIRES_IN`, and
  `JWT_REFRESH_EXPIRES_IN` are set in-process to disposable, non-real
  placeholder values by each spec file, as already established in the
  codebase; no `.env` file was read or inspected, and no credential value
  appears anywhere in this report.
- Two endpoints not exercised by any existing permanent spec (`GET /` and
  `GET /docs.json`) were verified in this session using a temporary,
  disposable diagnostic spec against the same harness (`supertest` +
  `createApp()`), following the same pattern as the prior run. It was
  deleted immediately after evidence was collected and is not part of the
  delivered changes (`git status` confirms no test file remains added).
- Cloudinary/upload endpoints were exercised safely via the project's own
  `FakeImageStorageAdapter`, injected through `createApp({ imageStorage })`.
  No real network call to Cloudinary was made at any point in this session
  (FR-006/AC-006). This is a durable improvement over the prior run, which
  could not exercise the upload/delete success path at all without risking
  a real Cloudinary call.
- No production environment, production database, or production
  credentials were used at any point (FR-007, NFR-002).
- Build (`npm run build`), unit tests (`npm test`), and the full permanent
  E2E suite (`npx jest --config ./test/jest-e2e.json`) were all re-run
  fresh in this session; results are reported under "Build/Test/Lint
  Status" below.

### Stateful flow verification (FR-005, AC-005)

The following flows were run **in dependency order** by the permanent
suites exercised in this session, not as isolated calls:

1. `POST /auth/login` → `GET /auth/session` (Bearer from login) →
   `POST /auth/refresh` (CSRF header omitted then included, cookies
   rotated) → `POST /auth/logout` (using refresh's rotated cookies) →
   `GET /auth/session` (confirms prior access token now rejected).
   (`app.e2e-spec.ts`)
2. `POST /works` → `POST /works/:workId/comments` → `GET
   /works/:workId/comments` (confirms pending comment excluded) →
   `PATCH /admin/comments/:id/approve` → `GET /works/:workId/comments`
   (confirms now-approved comment included) → `PATCH /admin/comments/:id`.
   (`comment-moderation-flow.e2e-spec.ts`)
3. `POST /works` → `POST /admin/works/:workId/images` → `GET /works`
   (confirms image reflected) → `DELETE /admin/works/:workId` (confirms
   image-cascade delete called, work removed from subsequent `GET
   /works`). (`admin-work-hard-delete.e2e-spec.ts`)
4. `POST /works` (`status: draft`) → `GET /works?includeDrafts=true`
   unauthenticated (`401`, no leak) → authenticated (`200`, draft
   present). (`works.e2e-spec.ts`)
